# 검증 기록

검증일: 2026-09-30. macOS, Node 24.15, Chrome / Playwright. 늘보군·토끼찬구의 코드 기반 캐릭터 프리셋과 격리된 SQLite DB를 사용했습니다.

## 하네스 통합 재검증

2026-09-30, `plan-002-harness-git-rules` 작업에서 `npm run verify` 전체 통과:

- 구조 검사와 실제 Git 상태를 포함하는 implementation 검사 통과.
- Python 하네스 회귀 10개, 실제 임시 Git 저장소 정책 회귀 13개 통과.
- 서버·DB·이미지·E2E 서버 수명주기 48개 통과(56.4초).
- 빌드된 앱과 전용 임시 DB에서 브라우저 10개 통과(43.2초).
- 총 81개 테스트, Prettier·TypeScript·Vite 빌드 통과.
- PR 메타데이터의 정상 제목/계획 허용, 잘못된 제목/계획 거부 확인.

기존 개발 DB를 재사용하던 E2E를 종료 시 정리되는 별도 서버로 변경했다. 실제 API 키를 비우고 기존 4173 포트 서버를 재사용하지 않는다. 배포용 HTML의 절대 경로가 숨김 worktree 상위 디렉터리에서 404를 일으키는 문제를 발견해 trusted dist root 기준 파일 제공으로 수정했으며 숨김 경로 회귀 검사를 추가했다. 첫 실패한 브라우저 실행은 통과 수에 포함하지 않았다.

아래는 앱 기능 구현 당시의 검증 기록이며, 새 테스트 수와 하네스 실행 방식은 이 절을 따른다. 원격 CI와 병합 상태는 실행 계획·PR에 별도로 기록한다.

- 서버·DB·이미지: `node --import tsx --test --test-concurrency=1 tests/*.test.ts` — **45개 통과**, 56.1초.
- 브라우저: `E2E_BASE_URL=http://127.0.0.1:3002 npm run test:e2e -- --trace off` — **10개 통과**, 45.0초.

## 캐릭터와 32/24종 검증

- 늘보군·토끼찬구 각각 정지 32개, 움직이는 24개를 전량 렌더링했습니다. 정지 64장·움직이는 48종 모두 대상입니다.
- 두 캐릭터 각각 32장 사이의 모든 496쌍을 72px 이미지 픽셀로 비교했습니다. 이름·대사·메타데이터만 다르게 바꾼 복제를 막기 위해 픽셀 차이 최소 4%를 검사했습니다. 실제 최솟값은 늘보군 5.65%, 토끼찬구 6.12%였습니다.
- 움직이는 48종 모두 실제 GIF/WebP로 디코딩했고, 3개 이상의 서로 다른 원본 자세, 2초 반복, 투명 여백, WebP 650KB 이하를 확인했습니다.
- 얼굴·몸통의 고정 기준 영역은 프레임 간 픽셀이 같고, 동작 부위는 변화합니다. 그림 전체를 흔드는 전역 이동을 쓰지 않습니다. 모든 장면에서 변화량은 60픽셀 이상이면서 전체의 15% 미만입니다.
- 개별 프리셋 수정은 선택한 장면의 표정·자세를 변경합니다. 포즈 ID와 감정은 유지하며 대사만 변경한 버전은 포즈 변주 순서를 진행시키지 않습니다.
- AI 경로는 각 슬롯마다 다른 장면·자세·동작 지시를 보내고, 동일 픽셀 결과가 여러 슬롯에 저장되는 것을 거부합니다. AI 수정 시 원래 슬롯 인덱스와 현재 프레임 순서를 유지합니다.

## 컨셉·대사·개별 수정

- 메인 캐릭터 컨셉 아래 여러 정지/움직이는 세트를 만들며 컨셉별 세트 수·이모티콘 수와 이력을 저장합니다.
- v4 마이그레이션으로 기존 프로젝트를 소유자·캐릭터별 컨셉 아래 묶고 기존 이미지, 수량, 검수 상태와 버전을 보존합니다. 부모 컨셉을 바꿔도 이미 만든 세트의 컨셉 기록은 변하지 않습니다.
- 개별 수정 후 나머지 31개·23개의 이미지 URL·버전·ID를 비교해 변화가 없음을 확인합니다.
- 상황별 대사 선택, 개별 문구 변경, 대사 제거, 버전 복원을 검사합니다. 한국어 글자와 불투명한 밝은 말풍선을 이미지에 합성해 내려받은 파일에도 남습니다.
- 어두운 배경과 흰 배경 위에서 글자·말풍선 대비를 확인했습니다. 모든 애니메이션 프레임의 대사 영역은 동일합니다.
- 대사가 없는 원본 PNG/프레임 시트를 별도로 보존합니다. 대사를 넣었다 빼도 원래 픽셀이 복원되며, 반복 합성으로 캐릭터가 계속 작아지지 않습니다.
- 대사 수정은 AI 호출·이미지 생성 사용량을 소비하지 않습니다. 24자 초과·빈 문구·숨은 제어 문자를 거부하고 원본 파일에도 소유권을 적용합니다.

## 기존 기능 회귀 검증

- 컨셉 → 추천/직접 입력 방향 → 생성 → 검수·수정 요청 → 이전 버전 복원 → 전체 승인 → 완료 → ZIP 내보내기
- 게스트 작업 저장, 가입 시 승계, 로그아웃·재로그인, 기존 계정으로 로그인할 때 게스트 컨셉·세트·업로드 이전
- 다른 계정의 컨셉·세트·이미지 조회/변경 차단, Origin 검증, 파일 내용·크기·투명도 검증
- 정지 32개·움직이는 24개 서버 강제, 부분 성공만으로 완료/내보내기 우회 차단, 누락분만 재시도
- 실제 PNG 크기·알파, GIF/WebP 프레임·재생 시간과 ZIP manifest 확인
- 재시작 복구, 진행 중 종료, 일일 사용량 예약·실패한 미시도분 반환, 프로젝트 삭제 후에도 한도 유지
- 저장 실패 시 새 파일만 정리하고 이전 이미지·수정 의견·DB 무결성 보존
- 프레임별 검수, 재생/정지, 첫·끝 비교, 움직일 영역 경계, 모션 줄이기 설정, 이전 전체 그림 효과 기록 보존
- 이미지 GET/HEAD는 분당 2,000회로 제한하고 일반 API 분당 240회와 분리했습니다. 다수 이미지를 읽어도 편집 API 예산을 소진하지 않으며 인증 제한은 유지합니다.

## 브라우저와 수동 검수

자동화는 컨셉 생성·세트 생성·정지 32개·움직이는 24개·대사 추가/제거·한 장 수정·새로고침·계정·다운로드를 다룹니다. 390px 모바일 가로 넘침과 WCAG 2 A/AA·2.1 AA 자동 규칙을 검사했습니다. 대시보드·새 컨셉·새 세트·검수 모달 모두 자동 접근성 위반 0건입니다. 접근성 자동 검사는 전체 인증을 대신하지 않습니다.

개발 서버의 실제 Chrome에서도 `토끼찬구의 이야기` 컨셉 아래 다음 두 세트를 만들었습니다.

- `토끼찬구 · 오늘의 한마디 32`: 32개 완성, 첫 이모티콘 대사를 `오늘도 반가워!`로 변경
- `토끼찬구 · 움직이는 마음 24`: 24개 완성, 첫 이모티콘 개별 수정 v2와 버전 이력 확인

디스크 공간 부족으로 첫 브라우저 실행이 중단되어 해당 실행 결과는 통과 수에 포함하지 않았습니다. 테스트 임시 DB·기록만 정리하고 재실행했습니다. 그 과정에서 대사 버전이 포즈 변주 순서에 영향을 주는 문제, 비동기 수정 실패 시 피드백이 사라지는 문제, 이미지 읽기가 일반 API 한도를 소진하는 문제를 수정했습니다. 서버 전체 검사에서 제공자 테스트 1건이 일시적으로 실패한 뒤 분리 실행 6개 및 파일 변경 종료 후 전체 45개가 통과했습니다.

## 실제 AI 및 운영 검증의 범위

이번 32/24종은 코드로 작성한 캐릭터 프리셋입니다. 이번 작업에서 AI로 112개 그림/동영상을 생성했다고 주장하지 않습니다. 기존 늘보군 6장과 손 인사 시트의 AI 제작 이력은 별도로 보존합니다.

`OPENAI_API_KEY`가 없어 앱의 유료 OpenAI 호출은 실행하지 않았습니다. 실제 생성 경로는 정상·실패·중복·참고 이미지·프레임 수정·사용량 예약의 **모의 upstream 응답**으로 검증했습니다. 임의 컨셉과 자연어 수정 지시의 실모델 결과 품질은 키 연결 후 별도 검수가 필요합니다.

이 검증은 로컬 배포용 빌드 기준입니다. Docker 이미지 빌드, 원격 CI, 실제 HTTPS 배포와 결제는 실행하지 않았습니다. 카카오 수량과 제출 적합성의 구분은 [공식 가이드 확인 기록](KAKAO-GUIDE.md)을 참고하세요.
