# 구현 순서와 미확정 결정

이 문서는 백로그다. 구현을 시작할 항목만 별도의 `plan-NNN-<task>.md`로 전환한다. 아래는 예약된 계획 번호가 아니다.

| 순서 | 작업 | 먼저 확인할 사항 | 인수 기준 |
|---|---|---|---|
| 1 | 기술 선택과 최소 앱 셸 | 로컬/서버 저장, 인증, 배포 대상, 공식 문서, 예상 비용 | 선택 이유·대안·실제 install/dev/test/lint/typecheck/build 명령을 기록하고 최소 화면 실행 |
| 2 | 캐릭터·바이블·참조 | 이미지 저장/권한/삭제, 도메인 버전 | 한 캐릭터에 참조 등록·수정, 바이블 버전 보존 |
| 3 | 프로젝트·기획·스토리보드 | 사용자 지정 프리셋과 목표 개수 | 생성 전 문구·순서를 수정하고 같은 캐릭터로 여러 세트 관리 |
| 4 | 생성/편집 공급자 어댑터 | 참조·편집 지원, 데이터 보관 정책, 비용 상한 | 가짜 공급자로 흐름 검증 후 승인된 실제 호출, 실패·취소·재시도와 계보 보존 |
| 5 | 정지 검사·ZIP | 최신 공식 규격 확보와 룰별 출처 | 경계값·잘못된 형식·중복 이름·선택 변경 후 재검사 테스트 |
| 6 | MVP 1 사용자 흐름 검증 | 앞 단계 완료 | 등록부터 ZIP까지 반복 가능, 비용·실패 표시, 미검증 규칙은 unknown |

카카오 출처 확인은 1단계부터 병행한다. 정지 이미지 구성 수치는 확인했고, 단계별 적용·용량 환산 등 남은 공백을 해소하지 못하면 사용자 지정 프로필 기반 흐름을 개발할 수 있지만 카카오 준비 완료 기능은 열지 않는다.

## 다음 단계에서 결정할 질문

- 우선 한 사람의 로컬 제작 도구인가, 로그인과 서버 저장을 제공하는 서비스인가?
- 선호하는 기술 스택·배포 환경·AI 공급자가 있는가?
- 월 예산과 한 번에 생성할 후보 수, 전송할 이미지 범위는 무엇인가?
- 최신 공식 안내서의 제안 규격과 AI 제작물 관련 본문을 확인할 수 있는가?

현재는 답을 가정하여 패키지·클라우드·AI SDK를 설치하지 않는다. 결정한 뒤 해당 계획 Decision Log와 [시스템 설계](../architecture/system.md)를 함께 갱신한다.
