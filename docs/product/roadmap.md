# 후속 작업과 미확정 결정

현재 앱 셸, 컨셉·세트 저장, 게스트·계정, sample/openai 생성, 버전 수정, 움직임·대사, ZIP 내보내기는 구현되어 있다. [제품 정의](product.md)의 현재 범위와 아래 백로그를 구분한다. 작업에 착수할 때만 별도의 `plan-NNN-<task>.md`를 만들며 아래 순서는 예약된 계획 번호가 아니다.

| 우선 영역          | 후속 작업                              | 먼저 확인할 사항                                  | 인수 기준                                                            |
| ------------------ | -------------------------------------- | ------------------------------------------------- | -------------------------------------------------------------------- |
| 저장소 운영        | 하네스·Git 정책 유지                   | 로컬 hook 설치, CI·원격 보호, 현재 앱과 문서 일치 | 규칙 위반 실패 검사, 재현 가능한 verify, PR 통합 기록                |
| 캐릭터 일관성 기반 | 버전별 바이블·구조화된 외형·다중 참조  | 기존 컨셉·세트 마이그레이션, 권리 기록, 자산 삭제 | 이전 세트·생성 버전 보존, 명시적 갱신·참조 선택                      |
| 생성 추적          | 입력 스냅샷·후보 계보·취소·비용 기록   | 공급자 지원·데이터 보관·요청 중복 처리            | 부분 실패 보존, 늦은 결과의 선택 덮어쓰기 방지, 알 수 없는 비용 표시 |
| 파일 규격          | 버전별 프리셋·결정적 검사·보고서       | 최신 공식 규격·단계별 적용·용량 환산              | 경계값·실제 형식·투명도 검사, 근거 미확정 unknown, 변경 후 재검사    |
| 내보내기 추적      | 검사 스냅샷과 ZIP 연결                 | 기존 manifest와의 호환성                          | 검사한 선택·파일 해시와 실제 ZIP 일치                                |
| 제품 운영          | 배포 환경과 계정 복구·운영 체계        | 실제 도메인·HTTPS·영구 저장·백업·예산             | 복원 검증, 운영 한도·장애 확인, 개인정보 안내                        |
| 후속 확장          | Reference Lock·일관성 평가·플랫폼·협업 | 측정 가능한 품질·사용자 승인·권한 경계            | 검증된 기준과 범위별 별도 계획                                       |

정지·움직이는 수량은 코드에 있으나 전체 카카오 제출 검사는 구현되지 않았다. 공식 규격과 AI 제작물 정책의 공백을 해소하기 전에는 “카카오 준비 완료”나 심사 통과를 약속하지 않는다. [카카오 기록](../KAKAO-GUIDE.md), [프리셋 설계](../architecture/platform-presets.md), [공식 출처](../references/official-sources.md)를 함께 갱신한다.

## 남은 운영 결정

- 실제 서비스의 호스팅·HTTPS·영구 볼륨·외부 백업·모니터링 담당과 복구 기준.
- 실제 AI 모델 사용 권한·비용 예산·계정별 및 전체 생성 한도.
- 메일 인증·계정 복구·협업이 필요한 운영 범위와 개인정보 보관·삭제 정책.
- 바이블·검사 보고서 도입 시 기존 세트·버전의 마이그레이션 방법.

스택 자체는 이미 선택되었다. 새로운 클라우드·유료 호출·데이터 전송이 필요한 작업은 그 목적과 범위를 계획 Decision Log에 기록한다.
