# Emoti Studio 제품 정의

캐릭터 하나를 만들고 AI와 함께 이모티콘 세트를 완성하는 제작 스튜디오. 사용자가 제공한 기획을 개발 가능한 범위로 정리한 문서이며, 아래 기능은 구현 목표다. 현재 저장소에는 문서와 구조 검사 도구만 있다.

## 사용자와 해결할 문제

개인 이모티콘 작가와 캐릭터 IP 보유자가 1차 사용자다. 한 캐릭터로 여러 세트를 만들 때 얼굴·비율·색·소품이 흐트러지는 문제와 생성 후 수정·선택·규격 정리를 반복하는 부담을 줄인다. 팀 협업은 후속 범위다.

## 핵심 원칙

1. Character와 Project를 분리한다. 한 캐릭터가 여러 주제의 세트에 재사용된다.
2. 모든 생성·수정 요청은 승인된 Character Bible 버전과 선택한 참조 이미지 버전을 기록한다.
3. AI 기획은 사용자가 편집하고 확정한 뒤 이미지 생성으로 넘어간다.
4. 사용자가 고른 후보를 수정의 기준으로 삼고 원본과 파생 이력을 보존한다.
5. 제출 규격은 UI·프롬프트에 흩어 넣지 않고 출처가 있는 버전별 프리셋으로 관리한다.
6. 파일 검사 통과, 캐릭터 일관성 판단, 플랫폼 심사 승인은 서로 다른 결과다.

## MVP 1 — 정지 이모티콘 제작

| 단계 | 필요한 기능 | 완료 기준 |
|---|---|---|
| 캐릭터 등록 | 이름·설명·성격, 구조화된 외형과 색·소품·선 스타일 | 저장한 바이블 버전을 다시 열 수 있다. |
| 참조 등록 | 정면·측면·후면·표정 분류, master/우선순위, 업로드 | 사용자가 선택한 참조와 사용 권한 확인을 보존한다. |
| 프로젝트 | 캐릭터 연결, 세트 이름·컨셉, 정지 유형·프리셋 버전 | 같은 캐릭터로 서로 다른 프로젝트를 만들 수 있다. |
| 기획 | 문구·감정·행동·표정 제안과 수동 수정·정렬 | 요구 개수는 프리셋에서 읽고 사용자가 생성 전 확정한다. |
| 스토리보드 | 항목별 상태, 진행률, 선택 이미지 | 진행률은 선택이 끝난 항목 수와 목표 수로 계산한다. |
| 생성 | 참조와 바이블을 포함한 요청, 복수 후보, 실패·재시도 | 요청과 결과의 연결이 남고 실패가 기존 후보를 지우지 않는다. |
| 수정 | 선택 후보를 기준으로 수정·재생성 | 새 후보와 부모 후보를 연결하고 기존 선택은 유지한다. |
| 검사 | 개수·크기·실제 형식·배경·용량·파일명·추가 파일 | 항목별 pass/fail/unknown과 근거를 보여준다. |
| 내보내기 | 검증된 선택 결과의 ZIP과 별도 검사 보고서 | 패키지를 검사한 결과와 실제 ZIP의 파일 해시가 일치한다. |

참조 시트 자동 분석, 영역 마스크 편집은 공급자 기능 검증 후 정한다. MVP의 기본 수정은 선택한 이미지와 수정 지시를 전달하는 흐름으로 시작할 수 있다. 후보 수는 구성값이며 기획의 4개 예시를 의무 수치로 삼지 않는다.

## 화면 구조

홈 → 캐릭터 목록·바이블 → 프로젝트 생성 → 기획 편집 → 스토리보드 → 항목 생성·수정 → 검사·내보내기. 설정에는 AI 공급자와 저장 방식을 선택한 뒤 필요한 항목만 둔다. 향후 AI 스튜디오·움직임 편집을 이 흐름에 확장한다.

## 후속 범위

- MVP 2: 특징별 Reference Lock, 일관성 검사, 사용자가 승인하는 자동 수정.
- MVP 3: Motion Plan → keyframe → 중간 프레임 → 타임라인·루프 검사 → 지원 형식 변환.
- MVP 4: 다른 플랫폼 프리셋, 팀 협업, 사용자용 버전 관리 UI.

초기 요청 추적용 내부 버전·수정 이력은 MVP 1에서도 필요하다. 후속 버전 관리 UI와 구분한다.

## 제품 표현과 범위

잠금은 특징 유지를 강하게 유도하는 기능이며 동일성을 보장하지 않는다. 일관성 점수의 검증 방법이 정해지기 전에는 기획의 97% 같은 수치를 정확도처럼 표시하지 않는다. 검사 완료 문구는 “선택한 규격의 파일 검사 통과”로 두고 카카오의 심사 승인이나 AI 제작물 허용을 뜻하지 않도록 한다.

카카오 직접 제출, 자동 계정 조작, 결제·광고·추적, 다른 창작자의 캐릭터 복제는 현재 범위에 없다. 실제 늘보군 시트는 이번 첨부에 없으므로 분석·등록한 것으로 간주하지 않는다.

## 미확정 결정

런타임·프레임워크, DB·이미지 저장소, 인증 필요성, AI 공급자·모델·비용 상한, 카카오 규격의 제안/상품화 단계별 적용·KB 환산과 AI 제작물 정책. 정지 이미지 구성 수치는 [공식 근거](../references/kakao-static-evidence.md)에 기록했다. [후속 작업](roadmap.md)과 [공식 출처](../references/official-sources.md)에서 해결 순서를 관리한다.
