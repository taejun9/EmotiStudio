# EmotiStudio

컨셉을 이모티콘으로 만드는 한국어 웹 스튜디오입니다. 캐릭터 컨셉 저장 → 같은 컨셉에서 정지·움직이는 세트 만들기 → 방향성 선택 또는 직접 작성 → 생성 → 개별 검수·수정 → 완료·다운로드 흐름을 제공합니다. 컨셉과 각 세트, 참고 이미지, 결과물, 대사, 검수 상태, 피드백, 이미지 버전, 작업 이력을 서버 DB에 보관합니다.

## 실행

Node.js **24.15 이상**이 필요합니다.

```sh
npm ci
cp .env.example .env
npm run dev
```

웹: http://127.0.0.1:5173 · API: http://127.0.0.1:3001

처음 접속하면 별도의 게스트 작업 공간과 늘보군의 이전 6종 예제가 만들어집니다. 이 예제는 `isLegacy` 기록이며, 새로 만드는 세트는 정지 32종·움직이는 24종입니다. 계정을 만들면 해당 작업을 유지하면서 다른 브라우저에서도 로그인해 이어서 작업할 수 있습니다. 게스트 기록은 서버에 저장되지만 쿠키를 잃으면 접근할 수 없으므로 중요한 작업은 계정에 연결하세요. 기존 계정으로 로그인할 때도 현재 게스트의 작업과 업로드를 해당 계정으로 옮깁니다. 생성 중에는 작업을 마친 후 로그인할 수 있습니다.

## 주요 기능

- 부모 캐릭터 컨셉에 이름·성격·대상·참고 이미지를 저장하고 여러 세트 만들기
- PNG/JPEG/WebP 참고 이미지 업로드, 늘보군·토끼찬구 프리셋 선택
- 컨셉을 반영하는 규칙 기반 방향성 3종, 직접 작성한 방향성
- 카카오 기준 수량: 정지 32개 / 움직이는 24개, 기존 작업 수량 보존
- 무료 프리셋: 캐릭터별로 서로 다른 정지 32종과 부위 동작 24종
- 서버 OpenAI 이미지 API로 자유 컨셉과 피드백을 반영하는 실제 AI 생성
- 팔·손목·눈·입·귀의 국소 동작, 실제 다중 프레임 GIF·WebP 저장
- 프레임별 재생·정지·이동, 첫/마지막 자세 비교, 동작 수정과 버전 복원
- 생성 진행률·실패 메시지, 중복 실행 방지, 실패한 작업 재시도
- 이모티콘별 승인·수정 요청, 피드백을 반영한 개별 재생성, 버전 비교·복원
- 한글 대사 켜기·끄기·편집: 대사 없는 원본에서 무료 재합성, 각 내보내기 프레임에 반영
- 전체 검수 완료 조건 확인, 다시 검수하기
- PNG ZIP 내보내기: 360/720/1024px, 투명도 유지, manifest 포함
- 움직이는 세트 ZIP 내보내기: 360px WebP 또는 GIF + PNG 포스터 + manifest
- 프로젝트 검색·상태 필터·수정·삭제, 작업 이력
- 이메일·비밀번호 계정, 세션 쿠키, 프로젝트·이미지 소유권 검사
- 데스크톱·모바일 화면, 키보드 탐색·대화상자·상태 안내

무료 `sample` 제공자는 `server/character-art.ts`의 코드로 작성한 벡터 캐릭터를 PNG와 동작 프레임으로 렌더링합니다. 늘보군은 베이지색 몸·크림색 얼굴·갈색 눈 무늬·초록 크로스백, 토끼찬구는 아이보리색 몸·한쪽 접힌 귀·민트 스카프·당근 가방을 유지합니다. `shared/sticker-plans.ts`에 정의한 인사, 사랑, 졸음, 감사, 식사, 작업, 우산 등 32개 독립 장면을 사용하며 앞의 24개 장면에는 각각의 동작이 있습니다. 이번 라이브러리는 이미지 생성 도구나 외부 AI 호출로 제작하지 않았습니다.

프리셋 개별 수정은 같은 장면의 표정·손 자세를 준비된 변주로 바꿉니다. 자유 입력한 수정 문장을 AI로 해석하지 않습니다. 임의 캐릭터에서 무료 예제를 선택하면 늘보군으로 미리보며, 입력한 캐릭터를 그린 것으로 표시하지 않습니다. 예전 6종 이미지와 손 인사 1종 반복 세트는 기존 버전 복원용 기록으로 남아 있습니다. 방향성 추천도 규칙 기반이며 외부 텍스트 모델을 호출하지 않습니다.

프리셋 애니메이션은 몸통을 고정하고 팔 관절·눈·입·귀를 프레임마다 다시 그립니다. 실제 AI 애니메이션은 동작 지시를 전달해 4열×2행의 연속 자세 시트를 생성합니다. 움직일 영역을 선택하면 그 밖을 생성된 첫 프레임으로 고정합니다. 한 장 전체를 회전·확대·이동시키는 생성 기능은 제공하지 않습니다. AI 결과는 원본 PNG와 같은 픽셀이나 자연스러운 연결을 보장하지 않으므로 프레임 검수를 거칩니다. 수량 기준과 플랫폼 제출 요건은 별개이며 [공식 가이드 확인 기록](docs/KAKAO-GUIDE.md)을 참고하세요.

대사는 이미지 생성과 분리되어 있습니다. 각 버전의 `cleanImageUrl`에는 대사 없는 PNG 또는 프레임 시트를 보존하고, 대사를 바꿀 때 이 원본에서 다시 합성합니다. 대사를 꺼도 이전 글씨가 남지 않으며 재합성은 AI 요청·생성량 한도를 사용하지 않습니다. Noto Sans KR을 프로젝트에 번들해 한글을 렌더링하고, 그림과 글씨의 영역을 나누어 PNG·GIF·WebP에 직접 넣습니다. 폰트 출처와 SIL OFL 1.1 원문은 [폰트 기록](public/fonts/README.md)에 있습니다.

## 실제 이미지 생성

`.env`에 `OPENAI_API_KEY`를 설정하고 서버를 다시 시작하세요. 키를 브라우저 환경 변수(`VITE_*`)에 넣지 마세요. `OPENAI_IMAGE_MODEL` 기본값은 `gpt-image-2`입니다. 실제 생성에는 등록된 계정과 모델 사용 권한·API 잔액이 필요합니다.

참고 이미지는 서버에서 검증한 파일만 사용합니다. 참고 이미지 없이 시작하면 첫 결과의 대사 없는 캐릭터 원본을 나머지 이미지의 기준으로 사용합니다. 생성 시 장면별 포즈·캐릭터 특징·방향성을 함께 전달하고, 개별 수정 시 대사 없는 현재 이미지와 수정 지시를 전달합니다. 움직이는 버전은 깨끗한 시트에서 첫 재생 자세를 추출해 위치 참조로 쓰고, 기존 시트와 재생 순서도 수정에 활용합니다. 다른 이모티콘의 기존 버전과 디코딩한 픽셀이 완전히 같은 AI 결과는 저장하지 않습니다. 이는 완전 중복 검증이며 시각적으로 비슷한 그림까지 판별하는 기능은 아닙니다.

실제 호출은 비용이 발생하며 사용자당 일일 생성량은 `MAX_DAILY_GENERATED_IMAGES`로 제한합니다. 서비스 전체 한도는 `MAX_GLOBAL_DAILY_GENERATED_IMAGES`(기본 96장/24시간)로 제한하며 프로젝트 삭제로 한도가 초기화되지 않습니다. 비공개 운영 시 `GENERATION_ALLOWED_EMAILS`에 허용할 이메일을 쉼표로 구분해 설정하세요. 비워 두면 가입한 계정이 한도 안에서 생성할 수 있습니다. 요금 청구·결제 기능은 포함하지 않습니다.

공식 구현 근거: [OpenAI 이미지 생성](https://developers.openai.com/api/docs/guides/image-generation), [이미지 프롬프트](https://developers.openai.com/api/docs/guides/image-prompting), [Node SQLite](https://nodejs.org/api/sqlite.html).

## 데이터와 운영

기본 데이터 디렉터리는 `./data`입니다. SQLite DB(`emotistudio.sqlite`)와 업로드·생성 이미지가 저장됩니다. 데이터 디렉터리 전체를 영구 볼륨에 보관하세요. 로컬 저장소이므로 서버리스 임시 파일시스템에는 배포하지 않습니다. 이 버전은 단일 Node 프로세스 배포를 기준으로 합니다.

```sh
npm run build
NODE_ENV=production npm start
```

프로덕션에서는 같은 서버가 웹 정적 파일과 API를 제공합니다. `.env`의 `APP_ORIGIN`을 실제 HTTPS 도메인으로 설정하고 HTTPS 역방향 프록시를 사용하세요. 컨테이너 예시:

```sh
docker build -t emotistudio .
docker run --name emotistudio -p 3001:3001 \
  --env-file .env -e NODE_ENV=production \
  -v emotistudio-data:/app/data emotistudio
```

앱은 API 키를 서버에만 두고 비밀번호를 scrypt로 해시하며, HttpOnly·SameSite 쿠키, 소유권 검사, Origin 검사, 요청 속도 제한, 입력 검증, 업로드 크기·픽셀 제한을 적용합니다. 데이터 디렉터리를 공개 정적 파일 경로에 연결하지 마세요.

작업을 잠시 멈추고 다음 명령으로 백업하세요. SQLite 스냅샷과 이미지 디렉터리를 함께 복사합니다. 복원할 때는 서버를 중지하고 백업의 DB와 이미지를 빈 DATA_DIR에 함께 넣습니다.

```sh
npm run backup -- /absolute/path/to/new-backup-directory
```

공개 상용 운영 전에는 실제 도메인·HTTPS, 영구 볼륨·외부 백업, 생성 API 계정과 비용 한도, 모니터링, 사업자 개인정보 처리방침을 운영 환경에 맞게 설정해야 합니다. 메일 인증·비밀번호 재설정 메일·결제·협업 공유는 현재 범위에 포함하지 않습니다. PNG 출력은 일반 이미지 패키지이며 특정 이모티콘 스토어의 심사 통과나 제출 규격 충족을 보장하지 않습니다.

## 검증

```sh
npm run verify
```

`npm run verify`는 구조·Git 규칙 회귀·형식·타입·서버 테스트·빌드·브라우저 검사를 순서대로 실행합니다. `npm run qa`는 브라우저 이전 단계까지 실행합니다. Node.js 외에 Python 3.9 이상이 필요합니다.

브라우저 테스트는 빌드된 앱을 `127.0.0.1:4173`에서 실행하고 매 실행마다 임시 DB를 만들며 종료 후 정리합니다. 기존 개발 서버와 `.env`를 사용하지 않고 실제 AI 키를 비웁니다. `npm run test:e2e`만 실행할 때는 먼저 `npm run build`를 실행하세요. 명시적으로 `E2E_BASE_URL`을 설정하면 그 서버의 데이터를 변경하므로 테스트 전용 서버만 지정하세요.

브라우저 테스트는 설치된 Google Chrome을 사용합니다. CI에서는 `npx playwright install --with-deps chromium`으로 브라우저를 설치하면 `CI=true` 환경에서 번들 Chromium을 사용합니다. API 테스트는 임시 디렉터리에 격리된 DB를 사용합니다. 실제 API 검증과 모의 응답 검증은 [검증 기록](docs/QA.md)에 구분해 기록합니다.

## 저장소 작업 규칙

작업은 [AGENTS.md](AGENTS.md)와 [Git 규칙](docs/quality/git-rules.md)에서 시작합니다. `npm ci`는 Git hooks를 자동 설치합니다. 기존 clone은 `npm run hooks:install`로 복구할 수 있습니다.

`codex/plan-NNN-task` 브랜치와 linked worktree에서 실행 계획을 작성한 뒤 구현합니다. 커밋 제목은 `fix(harness): 설명` 같은 형식, 본문은 `Plan: plan-NNN-task`를 사용합니다. QA와 별도 리뷰 후 PR을 만들고 필수 CI가 통과하면 main에 병합합니다. main의 직접 커밋·push는 로컬 hook에서 차단하며, 원격 보호 규칙은 저장소 설정에서도 관리합니다.
